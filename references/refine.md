# 精修：保留原稿，修正偏差

来源：用户提供的 `message (31).txt` 中 NAI 提示词编译部分。只在初稿不满意、出图偏差大、整理旧串、局部调整或角色隔离时加载；不是默认创作流程。未引入原 TXT 开头的小说/角色扮演执行政策。

## 先确定要改什么

从当前对话取得旧 prompt、结果反馈、参考图和目标。已有材料直接用；只在缺少待修改内容或关键目标、无法合理推断时简短询问。不要求用户重新填写模板。

优先级：用户当前明确要求 > 角色核心、旧串和必须保留项 > 人数、角色隔离、动作与构图 > 风格/色彩/材质补充 > 默认优化建议。

| 用户意图 | 允许的改动 |
| --- | --- |
| 优化、整理、改顺 | 保留角色、动作、服装、构图和视觉概念，清理错误、冲突及低效表达 |
| 只清理、不改内容 | 仅处理拼写、重复、格式和明确冲突，不补内容 |
| 改构图、人物换位置、背景主导 | 保留角色核心，调整镜头、位置、占比、空间层级和视觉重心 |
| 防串特征、两人老是串 | 划分共享与独占信息，加位置/身份锚点，明确双方关系 |
| 分开写、NAI 角色分栏 | 分成 Base Prompt、Character 1、Character 2 等代码块 |
| 只要串、不解释 | 只给最终代码块，仍遵守目标平台的格式例外 |

没有明确范围就保守精修。用户明确要求推倒重来、自由构思时返回 [创作方法](creation.md)，不把旧画面锁死。

## 保留边界

- 不擅自增加角色、文字、logo、道具、复杂背景或剧情，不改变人数、身份、外貌、服装、姿势及构图核心。
- 原串已有有效分区、竖线、权重和自然语言结构时，优先沿用；不为“更好看”重造画面或机械重排。
- 除非用户要求，或画风是所要求视觉概念不可分割的部分，不增删修改画风、线条、上色、媒介和渲染词。不要加“保持原有画风”等元指令。
- 不自动选 theme、凑环境实体或套配色；创作模块的补全默认值不在精修中执行。
- 默认不加泛质量词；用户明确要求时可保留或加入。不主动写比例、分辨率、图片尺寸或 canvas ratio。
- 静默修正常见重复、拼写、单双数和格式错误。标签拼写先区分 canonical、展示形式及符号标签；`=_=`、`^_^` 等不能因下划线被“修正”。必要时查 [知识库检索](knowledge-base.md)。

## 编译与冲突检查

依次提取不可变核心，划分全局/关系/角色属性，检查冲突，建立位置/大小/镜头/空间层级，补必要表达，去重，再判断 Negative 与输出格式。

先看作用域：不同角色的相反特征不冲突；同一角色的双色/渐变、单眼闭合或局部服装状态也可能共存。手、嘴、道具涉及多个动作时，检查能否同时成立，必要时明确左右、主动者和承受者。不能确定就保留，不擅自删词。

若原串结构不清，可按身份人数、外貌、表情视线、服装、动作道具、镜头位置、空间层级、环境材质、必要关系句排序；不拆散强关联词，不覆盖成熟原结构。

## 多人隔离

NAI 有两个或更多独立外观角色时，按 [NAI 多人](nai-multi.md)组织全局与角色分区。已有有效竖线沿用；明确要求独立 Character Prompt 时分栏，二者不混用。

- 全局只放人数、场景、镜头、总体构图、共享光线/风格/关系/环境和共用道具。
- 每个角色区放身份、位置、动作、表情、发色发型、眼睛、身体特征、服装和独占道具。
- 每区有位置或身份锚点；易串位特征不放全局。双方相同的特征也在各自分区写清。
- 互动尽量从双方描述，明确谁做什么、另一方如何回应。
- 先靠分区、位置和语义邻近解决串位，再考虑必要权重。

这些保留与隔离原则可用于其他平台，但 NAI 的竖线、角色面板和权重语法不能直接套给 SD、Anima 或 Krea。

## 构图与设计调整

把要求落实到主体位置、大小、画面占比、镜头角度、前中后景、遮挡、动线和留白。用户要求人物小/背景主导时，明确远景、小人物、大留白和背景主导，处理与之冲突的近景、大头像、人物填满画面等词。

抽象感觉要有可见落点：孤独可通过人物距离和留白，压迫可通过尺度和包围关系，干净可通过轮廓和间距，冲击可通过主导形状、对比和动线表达。只选符合当前修改范围的手段，不把示例当添加清单。

普通精修优先角色识别、动作和服装，不无故缩小、裁切或抽象化角色。只有用户要求艺术化、海报化、概念图、拼贴、抽象、故障、几何、负空间或“不要普通立绘”时，才启用设计调整：明确主导元素、人物占比位置、配色、元素与人物的穿插、脸眼避让、图层及情绪表达。修改仍服从已确认的范围。

## 权重、参考图与文字

- NAI 可使用花括号及数值权重，具体查 [NAI](nai.md)。只强化关键身份、稀有或易丢失特征、主导构图、关键动作和物件；不全面加权、不强化多个同义词、不用权重代替分区。
- 原串已有成熟权重体系时保留，只处理明显失衡。
- 参考图/反推/img2img 精修提取人数外貌、服装、表情、姿势道具、镜头占比、空间遮挡及必须保留项；不补图中没有的关键内容。原资料中的 preserve composition / preserve pose 等是可选约束表达，不是精确锁定效果的保证。
- 用户要求严格不改脸、姿势或精确局部编辑时，可简短说明专用图像编辑方式更适合此类控制，但仍交付可用的提示词。
- 未要求文字就不新增；需要文字时用引号写准确文案，明确位置、大小、字体、层级和遮挡。不加 random text、fake signature 或 watermark；NAI 具体方式查 [文字参考](nai-text.md)。

## Negative 与输出

默认不输出 Negative。用户要求，或明确存在跑偏、近景/居中/大人物干扰、加人/改脸/改衣/改姿势/遮脸、无文字/极简背景需求、多人身份互换风险时，才选择相关排除项，不机械附送整套负面词。

保持目标平台：默认 NAI 英文 TAG；SD/Anima 用 [对应语法](sd-anima.md)，普通 Krea 用 [中文自然语言](krea.md)，Krea 海报用 [纯英文正文](krea-poster.md)。这些平台规则优先于本模块的通用“代码块”约定，不自动转换平台。

单版本一个代码块，多版本各自分开；Negative 在需要时单独标注。块外只写必要中文说明，“只要串”时不解释。用户要求分析/评估/讲解时可以用中文展开，不强制只交付提示词。

交付前内部确认：角色核心和人数未漂移、双方动作清楚、属性没有串位、冲突与重复已处理、复杂关系明确、没有无故新增风格/文字/人物/道具/比例，以及 Negative 确有必要。
