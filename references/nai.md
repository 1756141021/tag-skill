# NAI 表达与权重

需要 NAI 语法、theme、自然语言细节，或实际出图、修图时读取；多人及文字分别按需查 [多人](nai-multi.md)和 [文字](nai-text.md)，不一次加载。

## 格式

默认以 Danbooru TAG 为主体，按画面需要混用自由英文短语与自然语言，表达动作与互动、身体摆放、空间关系、构图指令和概念融合；稳定视觉属性由 TAG 承担。技能不设自然语言句数、TAG 数量或提示词总长度的固定上限，画面完备优先。用户明确要求纯 TAG 时省略自然语言句子。

自然语言的四类用途及示例见[创作方法](creation.md#自然语言的创作用途)。

## 权重速查

- `{tag}` 加强，原稿记录每层约 x1.05；`{{tag}}` 约 x1.1025。
- `数值::tag::` 指定数值权重；`[tag]` 弱化，原稿记录每层约 x0.95。
- 收尾的 `::` 前留一个空格，例如 `0.8::artist:name123 ::`。前面的文字以数字结尾时一定要留，否则数字和 `::` 会被读成新的权重（如 `123::`），整张图变成彩色噪点。
- 语义相关词可以打包；核心突出，普通词保持原样。不要把角色分区问题交给高权重解决。
- 原稿记录过负数权重的定点抑制用法；需要时结合实际版本核对，不把经验效果视为保证。
- 不与 SD/A1111 的 `(tag:1.3)` 混用。跨平台转换语法，不直接照搬括号。

## 出图与修图

结构、头发、颜色等细节画错时，先改 NAI 提示词或画师串重画，不要习惯性交给 Nano Banana 修。改画师串可以大刀阔斧，不要只微调权重。

一次出一张，对照角色设定和现实中的结构严格检查，例如物体的形状和构造说不说得通；不要用户指什么就照抄，也不要接受有明显毛病的结果。

Nano Banana 只在用户要求或 NAI 确实做不到时使用。用户定好某个物件之后用 Nano Banana 修时（例如作品集的金钥匙），NAI 提示词不在这个物件上花词，写成 TAG 加一句简短的自然语言，集中写角色和姿势。

## Theme 的作用域

原技能的常规/SFW 首稿可主动选合适的现成 theme，优先颜色 theme，放在提示词前段适当加权。成人题材、其他平台不默认使用。

## 版本记录

原稿包含 V5/V4.5 的自然语言、提示词长度、多语言和角色定位经验。自然语言用于准确表达关系与创作概念，复杂画面按需要充分展开；按每段描述的实际作用检查重复。

本次是结构整理，未重新核验现行模型、容量或界面。任务依赖具体版本功能时先核对对应版本文档。
